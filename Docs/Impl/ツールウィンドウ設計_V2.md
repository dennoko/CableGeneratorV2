# CableGenerator V2 ツールウィンドウ設計書

Inspector を使わずに、専用のツールウィンドウとシーン上の操作だけでケーブルを作り切れるようにするための UI 設計。
見た目と画面の組み方は dennokoworks デザインスキル（`.claude/skills/dennokoworks_color_schema`）に従う。

- 対象バージョン: Unity 2022.3（2022.3.22f1 で確認）〜 Unity 6
- UI の実装方式: UI Toolkit（UXML + USS + `SerializedObject` へのバインド）
- 関連文書: [要件定義書_V2.md](要件定義書_V2.md) / [実装設計_V2.md](実装設計_V2.md)

---

## 1. 目的と方針

### 1.1 目的

- **説明書なしで操作できること。** 画面に出ている言葉とボタンだけで次の操作が分かるようにする。
- **見る場所を減らすこと。** ケーブルの形・断面プロファイル・出力を 1 つのウィンドウで扱い、プロファイルのアセットを選び直したり Inspector を縦にスクロールしたりしなくて済むようにする。
- **Inspector はふだん閉じておく。** 必要なときだけ開いて、情報を見て少し調整する程度の役割にする（§7）。

### 1.2 方針

| 方針 | 内容 |
| --- | --- |
| 作業の場所はウィンドウとシーンの 2 つ | 設定と出力はウィンドウ、形づくりはシーン（球・矢印・矩形選択・S1 ツールバー） |
| タブで画面を分ける | 4 タブ。1 タブにカード 3 枚まで、1 カード 7 行まで（スキル B2） |
| 値は 1 か所にだけ持つ | ケーブルの値は `CableGenerator`、断面の値は `CableProfile`。ウィンドウ・Inspector・シーンはどれも同じ `SerializedObject` を書き換えるので、どこで変えても他が追従する |
| 即時反映 | 「適用」ボタンは置かない。押して何かが確定するのはフッターの「出力」だけ |
| 公式の仕組みを使う | `EditorWindow.CreateGUI`、`PropertyField` + `Bind`、`ListView`、`Painter2D`、`ScriptableSingleton`、Overlay（§9） |

### 1.3 スキル上の位置づけ

スキルの画面パターン表（`blocks/patterns.md`）では CableGenerator は **P5 コンポーネント編集（Inspector）** に分類されている。
本設計では作業の入口を Inspector からウィンドウへ移すため、**P4 シーン作業の枠（ウィンドウで始め、作業はシーン）に、P5 の「値はコンポーネントに持つ」を組み合わせた形**にする。
画面全体の枠（トップバー・タブ・スクロール・フッター・ステータス）は P2 / P4 の共通枠、カードは B1〜B7 をそのまま使う。

## 2. 置き場所の分担

スキル `blocks/sceneview.md` §1 の分担を、このツールに当てはめる。

| 置き場所 | 担当すること | 置かないもの |
| --- | --- | --- |
| **ツールウィンドウ** | 対象の決定・新規作成、断面プロファイル、メッシュの細かさ、たるみ・床判定などケーブル全体の設定、制御点の一覧と数値の編集、出力 | — |
| **シーンの直接操作** | 制御点の選択（クリック・Shift / Ctrl・矩形）、移動（矢印）、接線、区間のたるみ（▼）、区間への制御点の追加（＋）、2点配線・なぞり描画の入力 | 設定値の変更 |
| **S1 シーンツールバー** | 作業中によく切り替えるもの: 配線モード、選択中の制御点の接線モード・投影・削除・アタッチ、床判定 / LOD のトグル、ウィンドウを開く | 出力先・出力形式・プロファイル（作業の前後に決めるもの） |
| **Inspector** | 状態の要約、よく変える 2 項目、ウィンドウを開くボタン、全項目の参照（詳細の中） | 配線・投影・出力などの操作 |

- S1 から **Bake / FBX のボタンを外し、「ウィンドウを開く」に置き換える**。出力はスキル上「作業の前後に決めるもの」なのでウィンドウに置き、S1 のボタン数（上限 12）にも余裕を作る。

## 3. 開き方と対象の決め方

### 3.1 ウィンドウの開き方

| 入口 | 動作 |
| --- | --- |
| メニュー `Tools/dennokoworks/Cable Generator` | ウィンドウを開く（1 つだけ。開いていれば前面に出す） |
| Hierarchy の右クリック `Cable Generator V2/Create Cable` | ケーブルを作り、ウィンドウを開いて「配線」タブを表示する |
| Hierarchy の右クリック `Cable Generator V2/Open in Window` | 選択中のケーブルを対象にしてウィンドウを開く（メニューのパスは翻訳できないので英語。§4.4） |
| S1 ツールバーの「ウィンドウを開く」 | 同上 |
| Inspector の「Cable Generator を開く」 | 同上 |

- ウィンドウは `EditorWindow.GetWindow<CableGeneratorWindow>()` で 1 つだけにする。既定のドック位置は Inspector と同じタブグループ（`desiredDockNextTo: typeof(InspectorWindow)` 相当。型が internal なので、取得できない環境ではフローティングで開く）。
- 開いていたタブ・詳細の開閉はウィンドウの `[SerializeField]` に持ち、エディタを開き直しても戻す。

### 3.2 対象（どのケーブルを編集しているか）

対象は B1 対象カードに出す。決め方は次のとおり。

| 状況 | 対象 |
| --- | --- |
| Hierarchy でケーブル（`CableGenerator` を持つオブジェクト）を選んだ | そのケーブルに切り替える |
| ケーブル以外を選んだ / 選択を外した | **直前のケーブルのまま**（配線中に床のメッシュをクリックしても画面が消えないようにする） |
| 子孫に複数のケーブルを持つオブジェクトを選んだ | 対象は変えず、B1 の下に候補の一覧（`.dennoko-candidates`）を出す。クリックで決定 |
| 対象のケーブルが削除された・シーンが閉じた | 空の状態にする |
| B1 の 📌（固定）を ON | 選択に追従せず、今の対象を保つ |

- 空の状態は B1 の中央に「ケーブルを選ぶか、新しく作ってください」+ **[＋ 新しいケーブル]**。
- [＋ 新規] は今の選択の子にケーブルを作る（何も選んでいなければシーン直下）。作ったら自動で対象にする。
- 対象名をクリックすると SceneView をケーブルに合わせる（スキル B7 と同じ動作）。

## 4. 画面全体の構成

```
┌ Cable Generator  v2.0.0 ↻                      EN ? ⋮ ┐  トップバー（.dennoko-appbar）
│ [🔌 Cable_01                          ▼] [📌] [＋ 新規] │  B1 対象カード（固定）
│ [ 配線 ][ 制御点 ][ ケーブルタイプ ][ 出力 ]            │  タブ（.dennoko-tabbar。固定）
│ ● 配線中  始点の表面をクリック     [Esc] で終了 [終了] │  B7 作業中バナー（配線中だけ）
├───────────────────────────────────────────────────────┤
│                                                       │
│   タブの中身（カード 3 枚まで）                         │  .dennoko-scroll（ここだけ縮む）
│                                                       │
├───────────────────────────────────────────────────────┤
│ 出力先 Assets/Cables      [選択…]  [FBX] [LOD0] [🦴12] │  出力ドック（要約チップ。§5.4）
│ 制御点 6 · 全長 2.40 m · 1,240△   [      出力      ] │  フッター（情報欄 + 主ボタン）
│ 保存: Cable_01.fbx                                     │  ステータスバー
└───────────────────────────────────────────────────────┘
```

| 部分 | 決まりごと |
| --- | --- |
| トップバー | スキルの標準ヘッダー。ツール名・バージョン・↻・マニュアル（?）・設定（⋮）。詳細は §4.1〜§4.3 |
| B1 対象カード | タブより上に固定し、どのタブでも同じ対象を見ていると分かるようにする |
| タブ | 4 つ（§5）。タブ名は作業の内容を表す名詞 1 語 |
| B7 作業中バナー | 2点配線・なぞり描画の間だけ表示。次の操作を 1 行で出す。「終了」と Esc とシーン側は同じ終了処理 |
| フッターの主ボタン | **どのタブでも「出力」の 1 つだけ。** 出力タブで選んだ形式で書き出す。メッシュが無いときは無効にし、ツールチップに理由を出す |
| フッターの情報欄 | 制御点の数・全長・ポリゴン数（LOD 有効時は `1,240→380△`） |
| ステータスバー | ウィンドウから実行した操作の結果（「3 点を投影しました」「保存: Cable_01.fbx」）。保存結果はクリックで Project ビューのファイルを Ping |

- シーンから実行した操作の結果はステータスバーに出さず、シーン側のトースト（S4）に出す（スキル「通知は実行した場所に 1 か所だけ」）。

### 4.1 標準ヘッダー（トップバー）

スキルの標準ヘッダー（`references/window-guide.md`「標準ヘッダー」、テンプレート `assets/EditorWindow/YourEditorWindow.uxml`）をそのまま使う。

```
┌ Cable Generator  v2.0.0 ↻                             EN  ?  ⋮ ┐
   appbar-title    version-label / version-reload-button   appbar-lang / appbar-manual / appbar-settings
```

```xml
<ui:VisualElement name="appbar" class="dennoko-appbar">
    <ui:VisualElement class="dennoko-appbar__title">
        <ui:Label name="appbar-title" text="Cable Generator" class="dennoko-title" />
        <ui:Label name="version-label" text="" class="dennoko-version-label" />
        <ui:Button name="version-reload-button" class="dennoko-icon-button" />
    </ui:VisualElement>
    <ui:VisualElement class="dennoko-appbar__actions">
        <ui:Button name="appbar-lang" text="EN" class="dennoko-appbar-lang" />
        <ui:Button name="appbar-manual" class="dennoko-icon-button" />
        <ui:Button name="appbar-settings" class="dennoko-icon-button" />
    </ui:VisualElement>
</ui:VisualElement>
```

| 要素 | 仕様 |
| --- | --- |
| ツール名 | 「Cable Generator」（`.dennoko-title`）。ウィンドウが狭いときはツール名だけが省略表示になり、右のアイコンは縮まない |
| バージョン + ↻ | §4.2。接続は `DennokoAppBar`（`assets/Shared/`）が行う |
| 言語 | **切り替え先**の言語を出す文字ボタン（日本語表示中は `EN`、英語表示中は `JA`）。§4.4 |
| マニュアル `?` | §4.3 |
| 設定 `⋮` | 上段にツール固有の項目、区切り、下段に共通項目（スキルの決まり）。<br>上段: 「メッシュを再生成」「シーンビューをケーブルに合わせる」<br>下段: 「設定を初期値に戻す…」（確認ダイアログあり。§8 のツール設定だけを戻し、ケーブルやプロファイルの値には触れない）、「更新を確認」 |

- 下罫線でスクロール領域と仕切るので `.dennoko-separator` は足さない。タブと作業中バナーはトップバーの直下に置く。
- アイコンは Unity 組み込みの `d_Refresh` / `d__Help` / `d__Menu`。見つからなければ ↻ / ? / ⋮ の文字。名前はツールチップに出す。
- Inspector（§7.2）では同じヘッダーの細い版（`.dennoko-appbar--compact`。ツール名なし）を使い、バージョン・↻・言語・?・⋮ を同じ動作で出す。
- **外部へのリンクは置かない。** マニュアルは同梱の PDF（§4.3）、更新の通知は文字だけ（§4.2）。

### 4.2 バージョン表示と更新チェック

スキルの `references/version-check-guide.md` と `assets/VersionCheck/` をそのまま使う。

**仕組み**

```
リポジトリ直下の version.json ─┬─ ローカル: GUID で読み込み → 現在の版（CableGeneratorVersion.Current）
                               └─ リモート: raw.githubusercontent.com/dennoko/CableGeneratorV2/<branch>/version.json
                                            → 最新版と更新メッセージ（6 時間に 1 回まで）
```

| 部品 | 内容 |
| --- | --- |
| `version.json`（リポジトリ直下 = `CableGeneratorV2/version.json`） | `{ "version": "2.0.0", "url": "", "message": "" }`。リリースのたびに `version` を上げてコミットする。ローカルとリモートで同じファイルを使う。外部リンクを置かないので `url` は空のままにする（スキル上、空でよい） |
| `DennokoVersionChecker.cs` | テンプレートをコピーし、**namespace を `CableGeneratorV2Editor` に変える**（他ツールの同名クラスとの衝突を防ぐ）。それ以外は変更しない |
| `CableGeneratorVersion.cs` | `YourToolVersion.cs` をコピーして変更: `VersionJsonGuid`、`RepoOwner = "dennoko"`、`RepoName = "CableGeneratorV2"`、`RepoBranch = "main"`、キーの接頭辞 `CableGeneratorV2_VerCheck_`、`CheckIntervalHours = 6` |
| 表示の更新 | テンプレートの `RefreshOpenWindows()` の代わりに `CableGeneratorVersion.Changed` イベントを出し、ウィンドウと開いている Inspector の両方がラベルを読み直す |

**表示**

| 状態 | 表示 | 動作 |
| --- | --- | --- |
| 確認中 | `v2.0.0  確認中...` | — |
| 最新 | `v2.0.0` | — |
| 更新あり | `v2.0.0  更新あり 2.1.0`（`.dennoko-version-label--update`。太字グリーン） | クリックしても何も開かない（`SetVersionClickable(false)`、`ReleaseUrl` は空）。ツールチップに「最新版 2.1.0 が公開されています」と `version.json` の `message` を出す |
| 取得失敗 | `v2.0.0  最新版を取得できません`（`--error`。警告色） | ↻ で再試行 |

- 自動の確認は 6 時間に 1 回まで（最後に通信した時刻を `EditorPrefs` に持つ）。↻ と ⋮「更新を確認」は間隔を無視してすぐ確認する。
- 通信に失敗しても例外は出さず、`Debug.LogWarning` に URL・HTTP コード・本文を 1 回だけ出す。
- **Unity 内から外部へのリンクは作らない**（スキルの「GitHub への直接リンクを作らない」より一歩進めて、配布ページへのリンクも置かない）。更新があることだけを知らせ、入手方法はマニュアルに書く。
- 状態ごとの文言（確認中 / 更新あり / 取得できません / ツールチップ）は §4.4 の翻訳表から引き、言語を切り替えたら表示中のラベルも読み直す。

### 4.3 マニュアル

| 項目 | 仕様 |
| --- | --- |
| 入口 | トップバーの `?`。Inspector の細いヘッダーの `?` も同じ |
| ファイル | 同梱の PDF。`Docs/user_manual_ja.pdf`（日本語）と `Docs/user_manual_en.pdf`（英語）。配布物（unitypackage / VPM）に必ず含める |
| どちらを開くか | 今の表示言語のもの。無ければもう一方の言語のものを開く |
| 探し方 | ツールのルートフォルダ（`version.json` の GUID → パス → そのフォルダ）からの相対パス `Docs/user_manual_<ja|en>.pdf`。フォルダごと移動されても見つかる |
| 開き方 | `EditorUtility.OpenWithDefaultApp(<絶対パス>)`（OS の既定の PDF ビューアー）。`DennokoAppBar` は変更せず、`ManualUrl` に `file:///<絶対パス>` を入れる方法でもよい。言語を切り替えたら入れ直す |
| 見つからないとき | `?` を無効にし、ツールチップ「マニュアル (PDF) が見つかりません」。ステータスバーにも 1 回だけ警告を出す |
| ツールチップ | 「マニュアル (PDF) を開く」/「Open manual (PDF)」 |
| 画面内の案内との分担 | 操作はマニュアルなしで分かるようにし（ツールチップ・空の状態・作業中バナー・カーソルヒント）、マニュアルには考え方・出力物の使い方（PhysBone の付け方など）・更新の入手方法・困ったときの対処を書く |

### 4.4 言語切替（日本語 / English）

| 項目 | 仕様 |
| --- | --- |
| 対象 | ウィンドウ・Inspector・S1 ツールバー（ツールチップ）・シーンのカーソルヒントとトースト・ステータスバーの文言・確認ダイアログ・Undo の名前・⋮ メニュー。マニュアルの PDF も言語に合わせる |
| 対象外 | `[MenuItem]` のパス（Unity の仕様で起動中に変えられない）。英語にそろえる: `Tools/dennokoworks/Cable Generator`、`GameObject/Cable Generator V2/Create Cable`、`GameObject/Cable Generator V2/Open in Window` |
| 切り替え | トップバーの言語ボタン。切り替えたら開いているウィンドウ・Inspector・S1・HUD がすぐに文言を読み直す（`CableL10n.Changed`） |
| 保存 | `EditorPrefs`（キー `CableGeneratorV2_Language`）。ユーザーの好みなのでプロジェクトをまたいで共有する |
| 初期値 | `Application.systemLanguage` が日本語なら日本語、それ以外は英語 |
| 翻訳表 | `Editor/Localization/ja.json` と `en.json`（キー → 文言）。GUID で読み込む。英語に無いキーは日本語、どちらにも無いキーはキーそのものを出す（抜けが画面で分かるように） |
| UXML の文言 | `text` / `tooltip` / `label` に `#キー` と書く（例: `text="#wire.tile.twoPoint"`）。読み込み後に `CableL10n.Localize(root)` が木を走査して置き換え、キーを覚えておいて言語切替時に入れ直す |
| C# の文言 | `CableL10n.Tr("status.projected", count)` のように引く。文言を C# に直接書かない |
| 幅 | 英語は日本語より長くなるので、ボタン・タブ・選択肢は英語の長さで崩れないか確認する。選択肢（`.dennoko-choice`、3 字まで）は英語では短い語にする（Auto / Smooth / Corner） |
| フォント | `DennokoUIFont.WarmupJapanese` に `ja.json` に出る日本語を全文字入れる（スキル `window-guide.md` の決まり）。EditMode テストで「`ja.json` の文字がすべてウォームアップに含まれる」ことを確かめる |

## 5. タブの中身

並びは作業の順（配線 → 制御点 → ケーブルタイプ → 出力）。ただし順番は強制しない（P2 の手順タブではなく通常のタブ）。

### 5.1 配線タブ — どこを通すか

```
┌ 引き方 ─────────────────────────────────────┐
│ ┌────────────────┐  ┌────────────────┐      │
│ │   ●────●       │  │   〰〰          │      │  大きい 2 択タイル。押すとシーンで開始
│ │ 2点をクリック   │  │ なぞって描く    │      │  作業中のタイルは selection 色の枠
│ └────────────────┘  └────────────────┘      │
│ 当たる対象  [Everything ▼]                   │
│ ▸ 詳細  [浮き 3mm] [簡略化 0.01]             │  閉じている間は値のチップ
└─────────────────────────────────────────────┘
┌ 制御点 ─────────────────────── [＋][⇄][⟺] ┐  ＋追加 / ⇄向きを反転 / ⟺等間隔に並べ直す
│ ☐ ループ                                    │
│ [0] スタート   [自動][滑らか][角]        ✕  │  ListView。シーンの選択と同期
│ [1]            [自動][滑らか][角]        ✕  │  Shift / Ctrl で複数選択
│ [2] エンド     [自動][滑らか][角]        ✕  │
│ ▸ 増やす  [4 等分] [自動]                    │
└─────────────────────────────────────────────┘
┌ 面に吸着 ───────────────────────────────────┐
│ 方向  [下][上][指定]       最大距離 [10 m]   │
│ [        選択中の 3 点を面へ投影        ]     │  選択が無いときは無効 + 理由
│ ▸ 詳細  [浮き 3mm] [ワールド]                │
└─────────────────────────────────────────────┘
```

| カード | 中身 | 状態 |
| --- | --- | --- |
| 引き方 | 2 択タイル（2点をクリック / なぞって描く）、当たる対象（LayerMask）。詳細: 裏面を無視（既定 ON。OFF のとき閉じた詳細に「裏面も判定」チップ）、ハンドルの長さ（2点）、面からの浮き・簡略化・サンプル間隔・作る制御点の種類（なぞり） | 作業中: 押したタイルに selection 色の枠、タイル内の説明が次の操作（「終点の表面をクリック」）に変わる。もう一度押すと終了。[やり直し] を出す |

- 出力（メッシュ / FBX / Prefab）にはアタッチメントのモデルを含める。コンポーネント（`CableKnotAttachment`）は含めない。

## 6. シーン操作との連携

### 6.1 配線の作業セッション

2点配線・なぞり描画は、スキル `blocks/sceneview.md` §4 のセッション規約に従う作業モードとして扱う。

| 項目 | 内容 |
| --- | --- |
| 開始 | 配線タブのタイル、または S1 ツールバーのボタン |

| 終了 | Esc、バナーの「終了」、タイル / S1 のボタンをもう一度押す。どれも同じ終了処理 |
| 自動終了 | 完了（2 点目のクリック・ドラッグを離す）、Play モード開始、シーン切替、再コンパイル前、対象の削除、ウィンドウを閉じる |
| 同時に 1 つ | 2点配線となぞり描画は同時に動かない（片方を始めたらもう片方を終える。既存の動作） |

### 6.2 選択の同期

| 場所 | 操作 |

| 配線タブの制御点一覧 | 行のクリック（Shift / Ctrl で複数） |

選択が変わったら `Changed` を出し、一覧の選択行・形タブ・S1 ツールバー・シーンの矢印がすべて読み直す。

## 7. Inspector の役割

### 7.1 既定で閉じておく

- ケーブルを作るとき（`Create Cable` メニュー、ウィンドウの ＋ 新規）に
  `UnityEditorInternal.InternalEditorUtility.SetIsInspectorExpanded(generator, false)` を呼び、Inspector 上でコンポーネントを畳んだ状態にする。
  Unity が「コンポーネントの折りたたみ」を保存している状態そのものなので、ユーザーが開けば次からは開いたまま。
- `Add Component` から手で付けた場合は畳まない（ユーザーが意図して付けたため）。

### 7.2 開いたときの中身

UI Toolkit の `CreateInspectorGUI()` で作る（スキル P5、`references/inspector-guide.md`）。

```
┌ ▼ Cable Generator (Script) ───────────────────┐
│ v2.0.0 ↻                               EN ? ⋮ │  細いヘッダー（§4.1。バージョン・言語・マニュアル・設定はウィンドウと同じ）
│ 制御点 6 · 全長 2.40 m · 1,240△ · LOD ON       │  情報行
│ プロファイル [HeavyDuty          ◉]             │  よく変える 2 項目（PropertyField）
│ 太さ        ━━━━●━━━━   [1.00]                  │
│ [         Cable Generator を開く         ]      │  主ボタン
│ ▸ すべての項目                                  │  閉じた状態が既定
└───────────────────────────────────────────────┘
```

- 「すべての項目」は全シリアライズ項目の `PropertyField` を並べるだけにする（参照と微調整用。操作ボタンは置かない）。
- 配線・投影・出力などの操作は置かない。Inspector から操作したいときは主ボタンでウィンドウを開く。
- **シーンのハンドルを `Editor.OnSceneGUI` から外す。** Unity は Inspector で畳まれたコンポーネントの `OnSceneGUI` を呼ばないため（段階 1 で実機確認する）、畳んだままだと球・矢印・S1 の対象通知が止まる。
  ハンドルの描画と入力は `SceneView.duringSceneGui` に登録した static ハンドラー（`CableSceneHandles`）に移し、対象は `CableSceneToolState.Target`（選択中のケーブル）から取る。Handles 自体は IMGUI のまま（UI Toolkit 版は無い）。

## 8. 状態とデータの持ち方

| データ | 持ち場所 | 理由 |
| --- | --- | --- |
| ケーブルの値（制御点・太さ・LOD・床判定・ボーン本数…） | `CableGenerator`（シリアライズ） | 今のまま。Undo・Prefab・複数 UI の同期が `SerializedObject` で自動になる |
| 断面の値 | `CableProfile`（アセット） | 今のまま |
| ツール設定（出力先・形式・FBX の LOD 段階・ボーン有無・配置・投影方向と距離・なぞり描画の設定・追加する点の種類・分割数） | `CableToolSettings : ScriptableSingleton<CableToolSettings>`（`[FilePath("UserSettings/CableGeneratorV2.asset", FilePathAttribute.Location.ProjectFolder)]`） | 今は `CableGeneratorInspector` の static フィールドと `EditorPrefs` に散っている。プロジェクトごと・ユーザーごとの設定として 1 か所にまとめ、Undo も効くようにする |
| 制御点の選択 | `CableKnotSelection`（static クラス。`Owner` / `Indices` / `Active` / `Changed`） | 今は `CableGeneratorInspector.s_selectedKnotIndices` / `s_snapKnotIndex`。ウィンドウ・シーン・S1 が共有するため Inspector から独立させる |
| 対象のケーブル・作業中かどうか | `CableSceneToolState`（既存）を拡張 | ウィンドウ・S1・シーンガイドが同じものを見る |
| 開いているタブ・詳細の開閉 | ウィンドウの `[SerializeField]` | エディタを開き直しても戻す |
| 表示言語 | `EditorPrefs`（`CableGeneratorV2_Language`） | ユーザーの好み。プロジェクトをまたいで共有する（§4.4） |

- 操作のロジック（配線・投影・細分化・出力など）は今 `CableGeneratorInspector` の partial に入っている。ウィンドウから呼べるよう、**`CableCommands`（static）に移す**。Inspector・ウィンドウ・S1 はどれも `CableCommands` を呼ぶだけにする。
